# Art Hackathon — Card Stack

`art-hackathon-query-api`의 검색 API와 `algorithm_team2/prototypes/06-card-stack` 화면을 통합한 독립 프로젝트입니다. 원본 저장소의 코드는 변경하지 않습니다.

## 실행

Node.js 22.9 이상, pnpm 11.25.0을 사용합니다.

```sh
pnpm install
pnpm setup:deconstruct   # 분해에 쓰는 Chromium 설치. 최초 1회
pnpm dev
```

개발 화면: http://127.0.0.1:5173 · 검색 API: http://127.0.0.1:3000 · 분해 API: http://127.0.0.1:3001

분해 서버는 메모리를 1.2~1.8GB 쓰고, 첫 실행 때 임베딩 모델 약 560MB를 내려받습니다. 필요 없으면 `DECONSTRUCT_ENABLED=false`로 끕니다. 꺼져 있거나 실패해도 검색은 그대로 동작합니다.

최초 구성 시 기존 API 프로젝트의 환경 설정을 루트 `.env`에 복사했습니다. 새 환경에서는 `.env.example`을 `.env`로 복사하고 `SERPAPI_API_KEY`, 선택한 LLM 공급자의 API 키를 입력합니다. 기본 공급자는 Anthropic이며 `LLM_PROVIDER=openai`도 지원합니다. 키는 서버에서만 읽으며 Git과 프론트 빌드에서 제외됩니다. `PORT`는 API/프로덕션 포트(기본 3000), `WEB_PORT`는 개발 화면 포트(기본 5173)입니다. 환경 설정을 변경하면 서버를 재시작합니다.

프로덕션 실행:

```sh
pnpm build
pnpm start
```

http://localhost:3000 에서 카드스택과 API를 같은 서버로 제공합니다. 빌드가 없으면 실행 안내와 함께 종료합니다. 외부 배포는 포함하지 않습니다.

## 검색 동작

- 실제 `GET /search`를 사용합니다. good 최대 10개, awesome 검색어 4개 × 검색어당 최대 2개를 요청합니다. 검색마다 유료 외부 API를 호출합니다.
- good은 원문 검색 결과이며 awesome의 1~4순위는 원문에서 점차 멀어지는 검색어 순위입니다. Google 문서 순위와 구분합니다.
- 카드는 순차 표시되고 선택 시 원문 iframe과 새 탭 링크를 제공합니다. 외부 사이트의 iframe 차단은 우회하지 않습니다.
- 선택한 카드의 제목으로 검색을 이어갑니다. 기존 카드·위치·히스토리는 유지되고 새 스택이 연결됩니다. 검색어 기록을 클릭하면 해당 스택으로 카메라만 이동합니다.
- 새 검색·화면 종료 시 이전 요청을 취소하며, 서버도 연결이 끊어진 요청의 외부 작업을 취소합니다. 오류·빈 결과·시간 제한에 따른 부분 결과를 그대로 표시하고 목데이터로 대체하지 않습니다.
- 가지 화살표는 시각화 규칙에 따른 연결이며 실제 문서 사이의 하이퍼링크를 의미하지 않습니다.
- 히스토리는 메모리에 보관하므로 새로고침하면 초기화됩니다.

## 분해 동작

- 선택한 카드의 "분해"를 누르면 검색과 같은 말 로딩 화면을 띄우고 `GET /deconstruct`를 호출합니다.
- 페이지당 약 $0.01~0.05가 들고 보통 8~21초 걸립니다. 같은 URL과 검색어는 화면을 새로고침할 때까지 최근 8개를 다시 요청하지 않습니다. 대기 중에는 취소할 수 있습니다.
- 화면 작업 중에는 루트 `.env`에 `SEGMENT_MODE=rule`과 `VISION_MAX_PER_PAGE=0`을 넣으면 LLM 비용 없이 같은 형식으로 응답합니다.
- 조각은 사각형 없이 글자와 이미지만 표시합니다. 사용자가 입력한 검색어(검색 이어가기를 하면 그 검색어, 검색 기록으로 이동하면 그 검색어)와의 유사도(`querySimilarities`)가 높을수록 진하고 큽니다. 값이 좁은 구간에 몰리므로 페이지마다 상·하위 5%를 뺀 범위로 늘려 쓰며, 투명도는 $\epsilon + (1 - \epsilon)t$ 이고 $\epsilon = 0.14$ 입니다. 패널에는 늘리기 전의 원래 값을 표시합니다.
- 보기 방식은 읽는 순서, 상호 유사도(가까운 4개를 끌어당기는 배치), 검색어 유사도(가까울수록 중심) 3가지이며, "3D" 버튼으로 각 보기를 입체로 바꿉니다(나선, 구름, 구체). 평면 보기에서 드래그는 이동이고, 3D 보기에서 드래그는 회전입니다. 휠은 확대입니다. 처음에는 살짝 확대되어 열리고, 빈 곳 더블클릭은 전체 보기입니다.
- 빨간 선은 응답 안에서 가중치가 상위인 쌍입니다. "연결 상위" 기본값은 0%라 처음에는 선이 없고, 조각을 고르거나 올리면 나타납니다. 값이 약 0.53~1에 몰리므로 백분위로 고릅니다.
- 조각을 누르면 전체 글, 유사도, 가까운 조각 5개와 "이 조각으로 다시 검색" 버튼이 나옵니다. 재검색은 그 글을 새 최초 검색어로 삼아 처음부터 검색합니다. 이미지는 `label`을, 없으면 가장 가까운 글 조각을 씁니다.
- "더 잘게 분해"는 조각을 Claude Haiku(`claude-haiku-5-5`)로 원문 순서대로 겹치지 않는 구절로 나누고, 분해 페이지 안에서 그 조각을 구절 조각들로 바꿉니다. 구절 조각도 다시 검색하거나 또 쪼갤 수 있고, "원래 문장으로 합치기"로 되돌립니다. 구절은 원문에 실제로 있는 부분만 통과합니다. 호출이 실패하거나 지출 한도에 닿거나 `SEGMENT_MODE=rule`이면 규칙으로 나누고 화면에 표시합니다. 호출당 비용은 약 $0.00005입니다.
- 구절 조각의 크기와 진하기는 자기 검색어 유사도를 따르고, 가까운 조각 목록은 원래 문장의 것을 물려받습니다. 구절끼리의 가중치는 계산하지 않습니다.
- "조립" 또는 Esc는 조각을 모아 같은 미리보기로 돌아갑니다. iframe을 다시 불러오지 않습니다. 조각을 선택한 상태의 Esc는 선택만 해제합니다.
- 페이지 글은 텍스트로만 출력합니다. 설명 없는 이미지가 나란히 있으면 앞뒤 글자가 같아 가중치가 근거 없이 높게 나올 수 있습니다.
- 공개 터널로 열면 누구나 유료 분해를 호출할 수 있습니다. 서버에는 아직 요청 빈도 제한이 없고, 지출은 `LLM_BUDGET_USD`(기본 $100)에서 멈춥니다.

## 구조와 검증

`apps/api`는 검색·LLM 서버와 기존 진단 화면, `apps/deconstruct`는 페이지 분해 서버, `apps/web`은 카드스택, `packages`는 공용 graph-contract·lab-kit입니다. 개발 서버는 `/search`와 `/deconstruct`를 각 서버로 프록시합니다. 프로덕션 서버는 빌드 화면, 생성된 assets, `/search`, `GET /deconstruct`만 공개하며 분해 서버 자체는 127.0.0.1에만 엽니다. 서버 생성 함수의 선택적 `frontendDir` 옵션을 생략하면 기존 API 진단 화면을 유지합니다.

```sh
pnpm check
pnpm test
pnpm build
pnpm test:deconstruct   # 분해 서버 테스트. Chromium 필요
```

테스트는 외부 API를 대체하며 실제 비용을 발생시키지 않습니다. 목데이터는 명시적인 격리 테스트나 `apiEndpoint: ''`로 지정한 테스트 마운트에서만 사용합니다.

상세 API 규약은 [API_SPEC](apps/api/API_SPEC.md)과 [분해 API 연동 가이드](apps/deconstruct/FRONTEND.md)를 참고하세요.
